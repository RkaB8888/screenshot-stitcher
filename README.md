# screenshot-stitcher

여러 장의 스크린샷을 겹치는 영역을 자동 인식하여 이어붙이는 CLI 도구.

## 목표

* 스크린샷 간 겹침 인식 및 정합

## 현재 상태

* 전제: 동일 배율(줌), 같은 원본 소스, 회전/반전/원근 왜곡 없음

* **기능**:
  * 입력 폴더 내 PNG 이미지 자동 로드 및 정렬
    * Windows 탐색기와 유사한 자연 정렬 키 사용 (숫자/문자 섞여도 직관적 순서 유지)
  * 회색조 + 알파마스크 변환 및 캐싱
  * **탐색 알고리즘 분기 지원 (`v1` / `v2`)**
    * **v2 (FFT 위상 상관 기법, 기본값)**: 고속 탐색 알고리즘. 대량의 이미지를 단 1초 만에 스티칭할 수 있는 압도적인 성능.
    * **v1 (브루트포스)**: 기존 픽셀 단위 정밀 탐색. tol, conf-min, slack-frac 옵션 및 라인 기반 프리체크, 중앙 k×k 미니패치 정밀화 지원.
  * 진행률 표시: 매칭(match) 단계와 정밀(refine) 단계 분리
  * **스티칭 분기 로직**
    * 모든 베젤 값이 0이면 → 단순 덮어쓰기(`_stitch_all`)
    * 하나라도 베젤 > 0이면 → 거리 기반 안티-베젤 스티칭(`_stitch_all_distance`)
  * 겹친 이미지를 이어붙여 PNG 저장
    * `--output` 미지정 시: 첫 파일명을 기반으로 `<이름>_stitched.png` 자동 저장
    * 유니코드 경로(한글/공백/특수문자) 안전 지원
  * **대화형(Interactive) 실행 모드**: CLI 인자 없이 `main.py` 실행 시 터미널에서 필수 옵션(경로, 방향, 베젤, 알고리즘)을 묻는 프롬프트 제공.
    * 알고리즘으로 `v1` 선택 시 샘플링 간격(`sample-step`)을 추가로 묻는 동적 분기 제공.

* **CLI 옵션**:
  * `--input`: 입력 폴더 경로
  * `--output`: 출력 파일명
  * `--direction`: 겹침 방향 (both/vertical/horizontal)
  * `--max-shift-ratio`: 탐색 범위 비율
  * `--tol`: 픽셀 차이 허용치
  * `--conf-min`: 신뢰도 임계값
  * `--slack-frac`: 흔들림 허용 비율
  * `--sample-step`: 매칭 시 샘플링 간격 (기본 8, 1이면 전체 픽셀 평가)
  * `--bezel`: 베젤 크기 (left,top,right,bottom, 기본 `10,10,10,10`)
  * `--prelim-refine`: 프리체크 시 중앙 k×k 미니패치까지 확인
  * `--method`: 알고리즘 선택 (`v1` 또는 `v2`, 기본값 `v2`)

## 실행 방법

**방법 1. 대화형 모드 (추천)**
파일을 더블클릭하거나 인자 없이 실행하면 터미널 프롬프트가 실행되어 직관적으로 옵션을 설정할 수 있습니다.
```bash
python main.py
```

**방법 2. CLI 모드**
기존과 같이 파라미터를 직접 전달하여 실행합니다. 백그라운드나 자동화 스크립트에서 사용하기 적합합니다.
```bash
python main.py --input ./images --method v2 --bezel 10,10,10,10
```

## 코드 구조

```text
screenshot_stitcher/
 ├─ cli.py            # CLI 인자 파싱 및 실행 흐름
 ├─ io_utils.py       # 이미지 로드 관련 함수
 ├─ preprocess.py     # 그레이 변환 및 마스크 처리
 ├─ overlap.py        # v1: 브루트포스 겹침 탐색 및 프리체크 로직
 ├─ overlap_v2.py     # v2: FFT 기반 고속 위상 상관 기법 및 정밀 검증 로직
 ├─ pipeline.py       # 이미지 정합 및 좌표 누적
 ├─ stitch.py         # 스티칭 및 DTB 기반 승자 규칙
 └─ progress.py       # 진행률/시간 표시
```
* `main.py`: 대화형 설정 래퍼(Wrapper) 및 실행 엔트리포인트

## 기술 노트 (FFT(v2) 알고리즘 트러블슈팅)

FFT(v2) 알고리즘 도입 시 발생한 수학적/좌표계 문제를 다음과 같이 해결하여 성능과 정확도를 확보했습니다.

* **이슈 1: FFT의 원형 간섭(Wrap-around Aliasing)과 선형 패딩(Linear Padding)**
  * **증상**: 겹침 이동량이 클 때, FFT의 원형 공간 특성으로 인해 역방향의 엉뚱한 값으로 계산되는 현상.
  * **해결**: 제로 패딩의 크기를 `max()`가 아닌 두 이미지 길이의 합(`h1 + h2`)으로 확장하여 캔버스를 2배로 늘림. 원형 간섭을 원천 차단하여 순수한 선형 이동량을 도출함.

* **이슈 2: 이미지 행렬 좌표계의 역전 현상**
  * **증상**: 파이프라인은 아래로 이어 붙이기 위해 양수(+) 오프셋을 기대하나, 스크롤 다운 시 픽셀은 물리적으로 위로(-y) 이동하여 음수 결과가 도출됨.
  * **해결**: `cv2.phaseCorrelate`의 입력 매개변수 순서를 `(img2, img1)`로 교체. "아래 이미지를 기준으로 위 이미지의 위치"를 역산하도록 변경하여, 별도의 부호 조작 없이 파이프라인 누적 좌표계와 동기화함.
